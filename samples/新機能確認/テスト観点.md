# 新機能確認データのテスト観点

`コールセンター記録.csv` を使って、PR #2 で追加した機能を手で確認するための観点です。正常系だけを扱います。

## データの概要

架空のコールセンターの受付記録です。600 行、26 列で、文字コードは UTF-8 です。受付日時は 2025 年 3 月 3 日（月）から 16 日（日）までの 14 日間にあります。平日は 1 日 50〜60 件、土日は 10〜14 件で、平日の 18 時以降の受付は少なめです。

列は、機能ごとに「自動で正しく判定される列」「手動で設定すると読める列」「判定されてはいけない列」に分けて作っています。

読み込み方は次のとおりです。

1. サイドバーの「新規作成」を押す
2. 「ファイルを選択」を押して `コールセンター記録.csv` を選ぶ（ドロップでも読み込める）
3. 読み込み後に「列の設定」タブを開く

作り直すときは `bun scripts/generate-feature-sample.ts` を実行します。乱数の種を固定しているため、何度実行しても同じ内容になります。

## 列と期待する判定

「列の設定」の種類欄には、判定の理由が「自動判定: 〜」と表示されます。下の表の文言は、実際の判定結果を写したものです。

| 列名 | 期待する種類 | 自動判定の理由として表示される文 | 使う確認項目 |
|---|---|---|---|
| 受付日時 | 日付・日時 | 値が日付の形式 | 3, 4, 5, 8 |
| 受付時刻 | 時刻 | 列名が時刻を示し、値が hh:mm | 3, 4 |
| 開始時刻 | テキスト（時刻ではない） | 値の種類が多い文章 | 2, 3 |
| 所要時間 | 時間の長さ | 列名が経過時間を示し、値が h:mm | 3, 4, 6 |
| 通話時間 | 時間の長さ | 値が 1時間30分 のような長さ | 3 |
| 保留時間 | 時間の長さ | 列名が経過時間を示し、値が h:mm | 3 |
| 解決済み | 真偽値（はい/いいえ） | 値が いいえ/はい の2種類 | 3, 6 |
| is_vip | 真偽値（はい/いいえ） | 列名がフラグで、値が 1/0 | 3 |
| 要折り返し | 真偽値（はい/いいえ） | 値が ×/○ の2種類 | 3 |
| created_at | 日付・日時（Unix 秒） | 列名と値の範囲から Unix 秒 | 3 |
| event_epoch_ms | 日付・日時（Unix ミリ秒） | 列名と値の範囲から Unix ミリ秒 | 3 |
| 受付日(欧州形式) | 日付・日時（日月年） | 日/月/年 の並びと判断 | 3 |
| 記録日時(独自形式) | テキスト（日付ではない） | 値の種類が多い文章 | 3 |
| 請求日(Excel) | 数値（日付ではない） | 値が数値 | 3 |
| 締め日 | 日付・日時（時刻なし） | 値が日付の形式 | 4, 5 |
| 売上 | 数値（前に「¥」） | 値が数値 | 1, 6 |
| 売上(千円) | 数値 | 値が数値 | 1, 3 |
| 単価(EUR) | テキスト（数値ではない） | 値の種類が多い文章 | 3 |
| 満足度 | 数値 | 値が数値 | 8 |
| 担当 | カテゴリ | 値の種類が少ない | 6 |
| 地域 | カテゴリ | 値の種類が少ない | 6 |
| チャネル | カテゴリ | 値の種類が少ない | 8 |
| 製品コード | カテゴリ（ID・コード扱い） | ID・コードと判断 | 3 |
| 性別 | カテゴリ（真偽値にならない） | 値の種類が少ない | 2 |
| 優先度 | 数値（真偽値・時刻にならない） | 値が数値 | 2 |
| 郵便番号 | カテゴリ（ID・コード扱い、日付にならない） | ID・コードと判断 | 2 |

次の点は、データを作る過程で分かったアプリの動きです。

- `event_epoch_ms` は、当初の案では `event_ms` でした。列名の末尾が `time`・`_at`・`timestamp`・`epoch` などでないと Unix 時間と判定されないため、`event_epoch_ms` にしています。
- `開始時刻` は `0830` のように先頭が 0 の値を含むため、数字だけでも数値になりません。
- 優先度は 1〜3 の 3 種類ですが、数値と判定されます。「新しい種類にならない」ことが目的のため、これで正常です。

## 確認項目

件数の値は、すべてこの CSV から計算したものです。日時は列の値のとおり、時差を含めずに表示されます。

### 1. 数値の表記と単位

- [ ] 「デザイン」を開き、「大きな数値の表記」が「1.2k・3.4M」のとき、「ウィジェットを追加」で種類「数値」、集計する列「売上」、集計方法「合計」の KPI を作る。値が「¥259.3M」と表示される（合計は ¥259,307,215）
- [ ] 「大きな数値の表記」を「1.2万・3.4億」にする。同じ KPI が「¥2.6億」になる
- [ ] 「省略しない」にする。「¥259,307,215」と表示される
- [ ] 集計方法を「平均」にして、3 つの表記を切り替える。「¥447.1k」「¥44.7万」「¥447,081」になる（平均は 580 件の値から計算）
- [ ] ウィジェットの設定の「数値の書式」で「大きな数の表記」を「省略せず全桁」にする。この KPI だけが全桁になり、ほかのウィジェットはデザインの設定のままである
- [ ] 同じ区分の「数値の前に付ける文字」を「$」、「数値の後ろに付ける文字」を「円」にする。この KPI の値が「$…円」の形に変わる
- [ ] 棒グラフ（分類する列「地域」、集計する列「売上」の合計）の軸に、単位を含む軸のタイトルが表示される。「表示」の「軸のタイトルと単位を表示する」を外すと消える

### 2. 型の自動判定（新しい種類にならない列）

- [ ] 「列の設定」で、性別の種類が「カテゴリ」、優先度が「数値」、郵便番号が「カテゴリ」になっている。真偽値・時刻・時間の長さ・日付にはなっていない
- [ ] 開始時刻（`0930` のような 4 桁）の種類が「テキスト」で、時刻になっていない
- [ ] 記録日時(独自形式)、請求日(Excel)、単価(EUR) が、それぞれ「テキスト」「数値」「テキスト」で、日付や数値として読まれていない（読ませる方法は 3 で確認する）
- [ ] 性別の欄が「値の種類が少ない」、郵便番号の欄が「ID・コードと判断」と表示される

### 3. 列ごとの解釈

「列の設定」の種類欄の右にある「解釈の設定」（スライダーのアイコン）を押すと、「（列名） の解釈」ダイアログが開く。値の変換結果は「変換の確認」に出る。

- [ ] 自動判定された列（受付時刻、所要時間、通話時間、保留時間、解決済み、is_vip、要折り返し、created_at、event_epoch_ms、受付日(欧州形式)）の種類欄に、上の表のとおりの理由が出る
- [ ] 受付日(欧州形式) の解釈を開くと「日付の書き方」が「日月年（05/03/2025）」になっている。「変換の確認」で「03/03/2025 → 2025/03/03」のように、日が先に読まれる。変換できない値はない
- [ ] created_at の「日付の書き方」が「Unix 時間（秒）」、event_epoch_ms が「Unix 時間（ミリ秒）」になっている。created_at の最初の値 `1740990121` は 2025/03/03 08:22 になる
- [ ] 開始時刻の種類を「時刻」に変える。解釈ダイアログの「時刻の書き方」を「時:分（秒は 00 とみなす）」にする。`0826` が 08:26 などに変換され、「変換できない値はありません（600 件を確認）」と出る
- [ ] 記録日時(独自形式) の種類を「日付・日時」にし、「日付の書き方」を「パターンを指定」、「パターン」に `DD.MM.YYYY hh:mm` と入れる。`03.03.2025 08:59` が変換され、変換できない値はなくなる。データの期間は 2025/03/03 08:49 から 2025/03/16 14:48 になる
- [ ] 請求日(Excel) の種類を「日付・日時」にし、「日付の書き方」を「Excel のシリアル値」にする。`45746` などが日付に変わり、期間は 2025/03/03 から 2025/04/13 になる
- [ ] 単価(EUR) の種類を「数値」にし、「小数点にカンマを使う（1.234,5）」をオンにする。`1.447,92` が 1,447.92 に変わり、変換できない値はない。合計は 726,499.55、平均は 1,210.83、最小は 10.54、最大は 2,399.19 になる
- [ ] 売上(千円) の解釈で「倍率」に `1000` を入れる。合計の KPI が「259.3M」（259,335,000）になる。入力を空にすると「259.3k」（259,335）に戻る
- [ ] 保留時間の解釈を開く。「「12:34」の意味」が「時間:分」の間は、`14:15` が 14 時間 15 分と読まれ、平均は 8時間10分、最大は 15時間59分になる。「分:秒」に変えると平均が 8分11秒、最大が 15分59秒になる
- [ ] 通話時間（`12分30秒`、`1時間5分` の形）の「変換の確認」で、変換できない値がない。平均は 16分21秒、最大は 1時間30分である
- [ ] 製品コードの解釈で「全角英数字を半角にする」をオンにし、「大文字・小文字」を「大文字にそろえる」にする。製品コードを分類にした棒グラフの項目が 15 種類から 5 種類になり、件数は ABC-01 が 111、ABC-02 が 129、DEF-10 が 116、GHI-20 が 123、JKL-30 が 121 になる
- [ ] 解釈を変えた列で「自動に戻す」を押すと、解釈が自動判定の状態に戻る。種類を変えた列は、種類欄の「自動判定に戻す」で元の種類に戻る

### 4. 時・分・秒の集計

- [ ] 種類「推移」のウィジェットを作り、日付・時刻の列「受付日時」、集計方法「件数」にする。「集計の単位」の候補に「自動」「秒」「分」「時」「日」「週」「月」「四半期」「年」が出る。「自動」では日ごとの 14 点になり、最初の日（3/3）は 53 件、最後の日（3/16）は 10 件である
- [ ] 「集計の単位」を「時」にすると、時間ごとの折れ線になる。軸の目盛りに日付と時が出る
- [ ] 「集計の単位」を「分」にする。「集計の単位」の下に「点が多すぎるため「時」単位で表示します」と出て、グラフの下にも「点が多すぎるため「時」単位で表示しています」と出る（14 日間の分単位は 約 19,600 点で、上限の 5,000 点を超える）。「秒」でも同じ文が出る
- [ ] 日付・時刻の列を「受付時刻」にする。「集計の単位」は「自動」「秒」「分」「時」だけになり、「時」で横軸が 8 時から 20 時になる。件数は 8時が 17、10時が 61、12時が 71、15時が 66、20時が 18 になる（ほかに 9時 31、11時 59、13時 54、14時 63、16時 53、17時 53、18時 36、19時 18）
- [ ] 日付・時刻の列を「締め日」にして「集計の単位」を「時」にする。「この列には時刻が含まれていないため、日単位で集計します」と出る。「分」「秒」でも同じである
- [ ] 種類「数値」の KPI で、集計方法「件数」、「前の期間との比較」をオンにして日付の列を「締め日」、期間の単位を「時」にする。同じ「この列には時刻が含まれていないため、日単位で集計します」が出る
- [ ] 種類「推移」で日付・時刻の列を「受付日時」、集計する列を「所要時間」の「平均」にする。縦軸の目盛りが「分」「時間」などの区切りのよい値になる（所要時間の最小は 40秒、最大は 1時間30分）
